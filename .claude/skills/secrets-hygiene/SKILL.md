# Secrets Hygiene

This account has hit this class of problem for real, more than once, this
session — a pasted API key, a dashboard URL with a live `connect_token` in
the query string. The rule that came out of that: nothing here is
hypothetical caution, it's a repeat of an actual event.

## Before any commit or PR

- **Grep the actual diff for secret-shaped strings** before staging —
  `sk_`, `pk_`, long hex/base64 tokens, `Bearer `, anything named `_KEY`,
  `_TOKEN`, `_SECRET` that has a real value rather than `process.env.X` next
  to it.
- **`.env` (and any `*.env.local`, `*.env.production`) must be in
  `.gitignore`** — check it's actually excluded, not just assumed to be.
  A `.env.example` with placeholder values (`sk_xxx`, `your-key-here`) is
  fine and often expected; a real value in a committed file is not.
- **Setup/README docs describe *where* a secret goes, never the secret
  itself.** "Set `ZERNIO_API_KEY` in Vercel → Environment Variables" is
  correct; pasting the actual key value into a markdown file, even in a
  private repo, is not — private repos get forked, made public, or leaked
  the same as any other file in git history, and history doesn't forget
  even if the file is later deleted.
- **Config/lockfiles generated by a tool** (e.g. an exported Postman
  collection, a `.vercel/project.json`, a database dump) can carry a
  captured token or connection string — check generated files with the same
  scrutiny as hand-written ones, not less.

## When a secret appears in chat

- **Treat it as already compromised the moment it's pasted**, regardless of
  whether it ends up used or committed — chat history, logs, and any tool
  that echoes the message back can retain it. Say so plainly and recommend
  rotating it, don't just quietly avoid writing it to disk.
- **Never write a pasted secret to any file, commit, or repository** — use
  it only in-memory for the single command that needs it (e.g. one `export`
  inside one shell call), and don't let it persist in a script, log file, or
  scratch file that outlives that command.
- **Never fetch a URL containing an embedded live token/secret in its query
  string** (a `connect_token=`, an `api_key=` parameter) without the user's
  explicit go-ahead for that specific action — treat it the same as handling
  the secret directly.

## Secrets this account actually has, so they're recognizable on sight

Kraken API keys (trading), a Telegram bot token/chat id, `ZERNIO_API_KEY`,
`ANTHROPIC_API_KEY`, `BEEHIIV_API_KEY`, `POSTGRES_URL`/Supabase connection
strings, Instagram/Meta Graph API tokens. Any of these appearing as a literal
value anywhere other than a deployment platform's environment-variable
settings is a finding, not a maybe.

## Process when this skill fires
1. If a secret was just pasted in chat: say plainly that it should be
   treated as exposed and rotated, and confirm nothing was written to disk
   or git with it.
2. Before staging a commit: grep the diff for the patterns above.
3. If something's found: stop, don't commit, and say exactly what and where
   — don't silently strip it and continue, since that can mask that a
   rotation is still needed.
4. If nothing's found, say so briefly rather than staying silent — a
   confirmed-clean check is still useful information.
